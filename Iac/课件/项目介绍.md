# 项目介绍

## 项目名称

基于公有云 IaC 与 GitOps 的 虚拟机 及 Kubernetes 自动化交付实战

## 项目背景

IaC（Infrastructure as Code，基础设施即代码）是用代码描述和管理服务器、网络及系统配置的方式，让环境能够自动创建、配置和回收。

传统方式依赖人工点击控制台、逐台执行命令，容易遗漏配置，也难以重复交付。IaC 将这些要求保存为代码，便于统一配置、追踪变更和重建环境。

| 对比项 | 传统方式 | IaC 方式 |
| --- | --- | --- |
| 交付方式 | 人工创建资源、执行配置命令 | 按代码自动创建和配置 |
| 环境一致性 | 依赖操作人员，容易出现差异 | 按统一配置交付，减少差异 |
| 变更管理 | 依赖手工记录 | 使用 Git 管理配置版本 |
| 环境重建 | 重复执行人工步骤 | 复用代码重新交付 |

本项目使用**阿里云杭州地域（cn-hangzhou）**，每位学生使用独立账号，创建 **1 台 control-plane 和 1 台 worker**，操作系统为 **Rocky Linux 9 x86_64**，用于部署 Kubernetes。云资源按量使用，实验结束后及时销毁；Semaphore、NetBox 在个人电脑部署，不额外占用云服务器。

**特别说明：由于本项目需要用到公有云，所以需要支付一定费用（大约15-20元），需要大家在阿里云自行充值，后续课程会具体说明。**

## 项目价值

- **基础设施标准化**：将镜像、网络、主机及系统配置写入代码，满足企业对环境一致性和重复交付的要求，降低手工操作风险。
- **交付效率提升**：通过 Packer 预制基础镜像、Terraform 自动创建资源、Ansible 自动初始化集群，减少反复安装与配置的工作量。
- **应用持续交付**：以 Git 保存期望配置，利用 Argo CD 自动同步、差异展示与自愈能力，发现并处理应用配置漂移。
- **变更可追溯与可恢复**：通过 Git 提交和 Argo CD 同步记录追踪发布，通过 Git revert 恢复历史配置，培养企业变更管理意识。
- **运维与成本管理**：借助 Semaphore 统一执行任务、NetBox 提供资产和主机清单，并通过定期销毁与残留检查管理实验资源和费用。

## 技术栈

- 云平台与系统：阿里云 ECS、VPC、交换机、安全组、云盘、Rocky Linux 9。
- 镜像与基础设施：Packer、Shell、Terraform、Alicloud 插件与 Provider。
- 配置与集群交付：Ansible、Inventory、Roles、containerd、kubeadm、Kubernetes。
- 集群网络与服务：Calico、CoreDNS、kube-proxy、Deployment、Service。
- 本地运维平台：Docker Compose、Semaphore UI、NetBox、PostgreSQL、Valkey。
- 版本管理与持续交付：Git、Gitee 等 Git 托管平台、Argo CD。

## 实战要求

1. 每天中午12点前发布任务和视频
2. 需要在第二天中午12点前完成任务并在项目群里输出当天任务完成的截图
3. 做的过程中有疑问可以在自己的专属服务群里提问

## 任务列表

### Day01：IaC 基础与 Packer 镜像制作

1. 理解 IaC 与各工具的分工，准备本地工具和个人云账号。
2. 使用 Packer 制作基础镜像，预装 containerd 并缓存容器镜像。
3. 记录镜像 ID，检查临时资源清理情况。

### Day02：Terraform 命令行资源交付

1. 学习 Terraform 配置、变量、Output 与 State。
2. 通过命令行创建网络和两台 ECS，验证登录与基础配置。
3. 完成资源变更、销毁与残留检查。

### Day03：Ansible 命令行自动创建 Kubernetes

1. 重建云主机，编写静态 Inventory 和 Ansible Playbook。
2. 自动完成系统初始化、Kubernetes 部署和节点加入。
3. 验证节点、网络与 DNS，完成后销毁实验资源。

### Day04：运维平台集成与首次 GitOps 发布

1. 本地部署 Semaphore、NetBox，接入资源交付与动态主机清单。
2. 通过平台重建集群，安装 Argo CD 并从 Git 完成首次应用同步。
3. 销毁实验资源，核对资产状态。

### Day05：GitOps 持续协调与总验收

1. 重建环境，验证 Argo CD 自动同步、自愈与资源清理。
2. 使用 Git revert 验证回退，完成全流程验收与记录整理。
3. 销毁实验资源并核对残留；扩容 worker 作为拓展练习。
